# KM Systems

**Websites, customer portals and business systems built around the way you work.**

KM Systems NZ Limited helps New Zealand businesses turn everyday problems into practical websites and software. The aim is to give each business a useful starting point, ownership of its project, and room to keep improving it.

[Visit KM Systems](https://km-systems.co.nz/) · [Explore the examples](https://km-systems.co.nz/examples/) · [Customer setup](https://setup.km-systems.co.nz/)

## What we're building

- **Business websites:** new sites, updates to existing sites, and a clear path from content and preview to launch and handover.
- **Customer and staff portals:** secure places for people to sign in, see their information, submit forms and use the tools relevant to them.
- **Business management systems:** adaptable workflows for jobs, schedules, documents, estimates, timesheets and team coordination.
- **A customer connection service:** one setup journey for arranging the website, source code, hosting, DNS and search access needed for the agreed work.

A business should be able to keep a website that already works and add a portal at an address such as `portal.example.co.nz`. Moving the entire website is an option when it makes sense.

## The customer experience

1. Tell KM what you have and what you want to improve.
2. Complete the setup form and connect the relevant services, or follow the manual invitation steps.
3. KM checks that access covers the correct website and agreed work.
4. Review the proposed changes or new system before launch.
5. Keep ownership, receive a handover, and improve the project yourself, with your developer, or with KM's help.

Quick connections and manual invitations belong to the same saved setup. Customers can start with the manual route and connect an app later.

## Where the project is now

| Area | Current position |
| --- | --- |
| KM website and examples | Public website and demonstrations are available. Demos illustrate workflows; they are not customer production deployments. |
| Customer setup | Live form, saved progress, provider guidance and private KM review. |
| Cloudflare | App connection and development/publishing tools are implemented. Customers approve the requested access; existing connections may need to reconnect. |
| GitHub | Customer-selected repository access and tools for proposing source changes on branches and draft pull requests are implemented. |
| Google Search | Optional Search Console setup and reporting where the customer grants the necessary access. |
| Other registrars and platforms | Manual invitations are available. Further automatic connections are planned where providers support them. |
| Customer rollout | Live customer-authorised pilots and provider-specific checks remain part of validating the complete workflow. |

The long-term goal is broad provider coverage. This is not a claim that every registrar, website builder or existing application can already be connected or migrated automatically.

## Ownership and careful changes

Customers choose the access they grant and retain ownership of their accounts and projects. New management applications are intended to have separate customer-owned resources and data. Connections to source code, hosting and DNS serve different purposes.

DNS changes need to preserve email and other services. Moving DNS does not copy a website, its users, memberships or paid subscriptions. Existing deployments need a tested publishing and recovery path.
